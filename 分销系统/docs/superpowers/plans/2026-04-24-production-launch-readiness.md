# 正式生产上线最小必要清单（500 用户版）

> **给执行型 agent 的要求：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务逐项执行。步骤使用复选框 `- [ ]` 语法追踪。

**目标：** 以当前大约 500 用户规模为前提，整理一份“够用、务实、能落地”的正式生产上线清单，优先完成真正影响上线安全和业务可用性的事项。

**适用前提：**
- 当前系统已经部署在 `test` 环境。
- 当前数据库是 `test` 环境下的云 MySQL，不是纯本地 SQLite 首发。
- 本次目标是从 `test` 平稳迁移到正式环境，而不是一次性完成所有大厂级生产化建设。

**原则：**
- 先做“上线不做就会出事故”的事。
- 再做“上线后一周内最好补上”的事。
- 对于 500 用户规模暂时不敏感、但未来会重要的能力，先记录，不作为本次上线阻断项。

---

## 一、上线前必须完成

这些事项是本次正式上线的**阻断项**。任何一项没完成，都不建议上线。

### 1. 正式 MySQL 准备与数据迁移

**目标：** 把正式环境数据库准备好，并确保当前业务数据、表结构、关键配置都能在正式库里正常运行。

**涉及文件**
- `faq-backend/app/db/session.py`
- `faq-backend/migrations/env.py`
- `faq-backend/PROD_MYSQL_CHECKLIST.md`
- `faq-backend/scripts/migrate_sqlite_to_mysql.py`（如需要）
- 数据库实例本身（控制台操作）

**必须完成**
- [ ] 创建独立的正式 MySQL，不能继续复用 test 库。
- [ ] 在迁移前对 test 数据库做一次完整备份。
- [ ] 明确本次迁移方案：
  - 方案 A：直接把 test 库完整迁到正式库。
  - 方案 B：正式库先建结构，再导入核心业务数据。
- [ ] 在正式库中验证以下核心表和数据可用：
  - `users`
  - `questions`
  - `answer_records`
  - `daily_quiz_rounds`
  - 认证资料、题库、指引、证书、兑换相关表（如果当前业务依赖）
- [ ] 确认应用启动时不会出现 schema mismatch。
- [ ] 上线前对正式库做一次启动联调，验证后端可以正常连通。

**重要说明**
- 如果你本次是“把 test 云 MySQL 整体复制到正式 MySQL”，那么“修好 Alembic 从空库启动”**不是本次上线阻断项**。
- 但如果你准备从一个全新空库开始正式首发，那么 Alembic 空库迁移链路就必须先修好。

**完成标准**
- 正式库已经准备好。
- 正式后端可以稳定连接正式库。
- 迁移后核心业务数据存在且可读写。

---

### 2. 正式环境 `.env` 与资源配置切换

**目标：** 让正式环境完全使用正式资源，不再回退到 test 或 stg。

**涉及文件**
- `faq-backend/.env`
- `faq-backend/.env.example`
- `faq-backend/app/core/config.py`
- `faq-miniprogram/config/env.js`
- `faq-miniprogram/config/runtime.js`
- `faq-miniprogram/app.js`

**必须完成**
- [ ] 为正式环境准备独立 `.env`。
- [ ] 至少确认以下配置全部替换为正式值：
  - `ENVIRONMENT=production`
  - `DB_TYPE=mysql`
  - `DATABASE_URL`
  - `SECRET_KEY`
  - `WECHAT_APPID`
  - `WECHAT_SECRET`
  - `HIAGENT_API_BASE`
  - `HIAGENT_API_KEY`
  - `COS_SECRET_ID`
  - `COS_SECRET_KEY`
  - `COS_REGION`
  - `COS_BUCKET`
  - `CORS_ORIGINS`
- [ ] 小程序 `release` 环境必须显式绑定正式 `cloudEnvId`。
- [ ] 正式版不能再自动回退到 `test` 的 `defaultCloudEnvId` 或 `legacyBaseUrl`。
- [ ] 发布前人工确认一次：`develop / trial / release` 三种环境的资源指向。

**重点风险**
- 当前代码里，正式版存在回退到 test 环境的风险，重点位置：
  - `faq-miniprogram/config/env.js`
  - `faq-miniprogram/config/runtime.js`

**完成标准**
- 正式版小程序只访问正式环境资源。
- 正式后端只连接正式数据库和正式外部服务。

---

### 3. 收住真正有业务风险的接口

**目标：** 把“用户量不大但一旦被绕过就直接出问题”的接口先收住。

#### 3.1 兑换功能

**涉及文件**
- `faq-backend/app/api/v1/energy.py`
- `faq-backend/app/services/energy.py`
- `faq-miniprogram/pages/energy-mall/index.js`

**必须完成**
- [ ] 二选一，必须明确：
  - 方案 A：上线前补后端校验。
  - 方案 B：正式环境先关闭兑换功能。
- [ ] 如果走方案 A，后端至少要做到：
  - 不再信任前端上传的 `cost`
  - 不再信任前端上传的 `status`
  - 服务端校验积分是否足够
  - 服务端校验商品是否合法
  - 防止重复兑换

**原因**
- 当前兑换接口还信任客户端提交的关键字段。
- 这和用户量无关，只要有人会抓包改请求，就可能伪造兑换行为。

#### 3.2 分销商数据接口

**涉及文件**
- `faq-backend/app/api/v1/distributor_data.py`

**必须完成**
- [ ] 如果该接口会暴露真实业务数据，则至少加登录鉴权。
- [ ] 如果正式阶段业务不依赖匿名访问，则不允许匿名枚举省份和公司。

**完成标准**
- 高风险接口不会因为前端被篡改或匿名访问而直接暴露业务风险。

### 4. 正式环境冒烟测试

**目标：** 上线前至少手动确认核心流程全部能跑通。

**必须完成**
- [ ] 登录
- [ ] 首页加载
- [ ] 每周答题
- [ ] 学习记录
- [ ] 个人资料
- [ ] 头像上传
- [ ] AI 问答
- [ ] 排行榜
- [ ] 证书查询（如果已上线）
- [ ] 产品指引（如果已上线）
- [ ] 兑换流程（如果正式环境开放）

**完成标准**
- 所有正式开放功能至少人工跑通 1 次。

---

### 5. 回滚方案

**目标：** 保证上线出问题时能快速止损。

**必须完成**
- [ ] 明确数据库回滚策略：
  - 是否保留上线前备份
  - 是否允许回切到旧库
- [ ] 明确应用回滚策略：
  - 是否保留旧镜像或旧配置
  - 是否能快速切回 test 或旧版本
- [ ] 明确回滚触发条件：
  - 登录大面积失败
  - 数据写入异常
  - AI 服务不可用
  - 上传功能不可用

**完成标准**
- 上线出问题时，团队知道“怎么退、退到哪里、谁来退”。

---

### 6. 正式环境初始化数据

**目标：** 保证正式环境不是“服务起来了，但内容缺失”。

**必须完成**
- [ ] 确认白名单用户已导入
- [ ] 确认题库已导入
- [ ] 确认认证资料已导入
- [ ] 确认产品指引数据已导入（如依赖）
- [ ] 确认证书数据已导入（如依赖）
- [ ] 确认兑换商品目录已准备（如依赖）

**完成标准**
- 正式环境上线后，用户进入系统不会遇到“页面能开，但没有数据”的情况。

## 四、本次上线建议的最小完成包

如果你想把事情收敛到最小，我建议这次只盯住下面 6 条：

- [ ] 准备独立的正式 MySQL，并完成 test -> prod 的结构/数据迁移
- [ ] 配好正式 `.env`
- [ ] 修掉小程序 `release` 回退到 test 的风险
- [ ] 兑换功能要么补后端校验，要么先关闭
- [ ] 给敏感数据接口加最基本鉴权
- [ ] 跑完一轮正式环境冒烟，并准备回滚方案

---

## 五、上线当天执行顺序

1. 备份 test 数据库和准备正式数据库
2. 导入正式数据或迁移 test 数据到正式库
3. 配置正式后端 `.env`
4. 配置小程序 `release` 指向正式资源
5. 部署正式后端
6. 做一轮冒烟测试
7. 再提交小程序正式版
8. 上线后观察日志和关键功能 30 到 60 分钟

---

## 六、一句话判断

对于你现在这个阶段，**不是所有生产化动作都要立刻做满**。  
但下面这四类绝对不能省：

- 环境隔离
- 数据库迁移
- 高风险业务接口收口
- 冒烟与回滚

只要先把这几件事做好，你这次 500 用户规模的正式上线就是可控的。
